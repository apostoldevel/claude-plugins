# agent-team

[Навык агента](https://docs.claude.com/en/docs/claude-code/skills) (Agent Skill) в виде плагина Claude Code. Он нужен,
чтобы вести разработку **вместе** с командой именованных агентов Claude Code, а не отдавать её целиком.

Агенты — долгоживущие сессии на переднем плане:
- координатор;
- по агенту на каждый языковой слой;
- QA и аудитор, когда до них дорастает нагрузка.

У каждого агента своя память. Координируются они через доску в git, а не в чате. Рабочий день открывается и закрывается
словом владельца.

Навык вызывается как `/agent-team`. Какие документы нужны проекту, описывает парный навык `/agent-onboarding`; этот — о
людях.

## Что получает агент

- **Выбор, который делается первым:** видимая именованная команда или автономный флот. Это не две разновидности
  одного и того же.
- **Двенадцать правил, у каждого указана цена, которой оно куплено:**
  - роли по языку и инструментам;
  - каталог запуска как личность агента;
  - четыре носителя знания (вики, история по дням, карточки, память как указатель);
  - доска в git, приоритеты как группы и очереди;
  - ревью запускает автор;
  - работа в полёте ограничена по людям;
  - шардирование;
  - барьер записи на каждый компонент;
  - цена того, что читается всегда;
  - рабочий день открывается и закрывается словом владельца;
  - слово владельца передаётся записью.
- **Чек-лист развёртывания** команды в новом проекте.
- **Шаблоны хуков**, проверенные:
  - барьер записи по ролям с положительным пропуском и самодостаточной приёмкой;
  - брифинг сессии по каталогу запуска с журналом очисток;
  - страж контекста с правилами 300k / 450k / простой;
  - фильтр вывода прогонов и сборок;
  - `settings.json` для координатора и для слоя.
- **Проверенные ловушки:** барьеры, хуки, валидаторы, деревья, числа. Каждая найдена проверкой.

## Установка

Из [маркетплейса apostoldevel](../../README.ru-RU.md#установка):

```
/plugin marketplace add apostoldevel/claude-plugins
/plugin install agent-team@apostoldevel
```

Сам навык — каталог [`skills/agent-team/`](skills/agent-team/). Шаблоны хуков **не** ставятся хуками плагина. Барьер
свой у каждого компонента и каждой роли, поэтому проект копирует шаблоны в свой `.claude/hooks/` и настраивает их
(`skills/agent-team/hooks.md`).

## Использование

Вызывайте `/agent-team`, когда собираете команду или когда у существующей появился один из признаков из описания навыка.
Агент читает правила в `SKILL.md` и открывает справочники по мере надобности.

## Состав

Пути даны от `skills/agent-team/`.

| Файл | Что в нём |
|---|---|
| `SKILL.md` | Часть I — выбор; часть II — двенадцать правил и нормы; часть III — чек-лист развёртывания |
| `day.md` | Рабочий день: `DAY`, открытие, семь шагов закрытия, фиксация состояния, проверка сводок |
| `hooks.md` | Обвязка: что делает каждый шаблон, как его настроить, зарегистрировать и проверить |
| `pitfalls.md` | Проверенные ловушки: барьер и хуки, роли и деревья, доска и карточки, инструменты, слово владельца |
| `apostol.md` | Применение в экосистеме Апостол (libapostol + db-platform) |
| `templates/` | Хуки и их приёмка, примеры `settings.json`, карточка, `PRIORITIES.md`, `DAY` |

## Допущения

- **Claude Code** с обменом сообщениями между сессиями (`SendMessage`, `ListAgents`) и хуками (`PreToolUse`,
  `SessionStart`, `PostCompact`, `UserPromptSubmit`, `PostToolUse`, `Stop`).
- Шаблонам хуков нужны `bash`, `jq` и GNU `realpath`.
- Замеры в тексте сделаны на одном боевом проекте экосистемы Апостол в августе–сентябре 2026. Числа вроде порогов
  контекста — настройки той команды. Считайте их умолчаниями.

## Обратная связь

одного проекта — в уставе этого проекта.
